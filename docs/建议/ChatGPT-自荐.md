# ChatGPT 的自荐与 12 周训练计划

> 对应文件：《36 周总计划与 AI 协作说明.md》2026-11-23 草案
> 角色定位：学习教练、英语陪练、文案与产品思考伙伴
> 适用阶段：第 1 个 12 周的第 3–12 周
> 原则：不替用户决定计划，不把用户培养成程序员；用最少的额外学习时间，帮助用户把内容、产品和 AI 协作任务做出来。

## 1. 我最有优势的 3–5 项能力（和其他 AI 平台相比）

| 能力 | 具体能做什么 | 相对优势 | 限制（付费 / 版本 / 访问） |
|---|---|---|---|
| 连续对话式教学与反馈 | 把复杂概念拆成适合零基础用户的步骤；根据回答判断是否理解；出题、纠错并要求用户重新表达 | 适合多轮练习、即时反馈和循序渐进的学习任务 | 仍可能讲错；重要技术结论应由实际测试、官方文档或其他模型交叉核验 |
| 英语口语与写作陪练 | 模拟工作、出差、产品介绍等场景；纠正语法和中式英语；提供自然表达及复述练习 | 能围绕用户真实工作和项目反复练习，而不是只做孤立题目 | 语音功能、可用模型和额度依账户及产品模式而异；以文字练习作为基础 |
| 中文内容策划与文案迭代 | 选题发散、视频结构、前三秒钩子、口播稿、标题、简介和评论回复；按目标观众反复压缩改写 | 适合把用户真实经历整理成清楚、可讲述的内容，并通过多轮讨论迭代 | 不能替代真实观众反馈、剪辑和平台数据；不能保证播放量或涨粉 |
| 产品需求梳理与用户视角挑错 | 把模糊想法整理成问题、用户场景、需求、验收标准和测试问卷；扮演新用户或挑剔买家 | 适合把早期想法变成可讨论、可验证的文字材料 | 不应代替真实访谈；市场规模、竞品价格、平台规则等事实必须查证并附来源 |
| 多模型协作与结果审阅 | 判断任务适合交给谁；制定提示词、交接说明、验收清单；比较不同模型输出 | 可作为跨模型讨论与整合层，帮助明确任务边界和验收标准 | 不能默认读取其他平台的私有对话，也不会自动同步其他模型工作；需要用户提供结果或通过已授权连接读取 |

**关于“比别的平台强”**：我不认为自己在所有任务上都比其他平台强。我的相对优势是持续对话、教学反馈、中文表达、英语练习和把讨论整理成可执行文本。代码实现交给 Claude Code / Codex；带出处的外部调研优先交给 Perplexity；视觉素材优先交给 Gemini；X 平台热点与用户声音优先交给 Grok。各模型应按任务分工，而不是争夺所有工作。

## 2. 在这份计划里，我建议承担哪些任务

### 建议交给 ChatGPT 的任务

- **第 3 周｜内容关**：协助确定前两条视频的叙事重点；为首条视频写 5 个前三秒钩子；把口播稿改成自然、可朗读的口语稿。
- **第 3 周｜ChatGPT 关**：负责首条视频口播稿的结构、口语化和删减。
- **第 4 周｜内容关**：提供第 1 条视频的 10 个标题和简介候选；协助选择，但最终由用户决定。
- **第 4 周｜ChatGPT 关**：整理标题、简介，并协助拟定 PPT 英文标题。
- **第 5 周｜产品关**：协助设计新用户问卷、目标可行度判断维度和规则初稿；由 Claude 实现，真实用户验证。
- **第 6 周｜Claude 关的辅助**：解释 Skill / 自定义命令的用途，比较命令说明写法；不代替 Claude Code 实际创建。
- **第 7 周｜产品关**：用访谈式提问整理产品大纲，包括目标用户、使用场景、核心价值、功能边界、定价假设和售卖方式。
- **第 8 周｜Skill 关**：一起打磨“口播稿润色”Skill 的规则、输入输出和测试样例；Claude Code 负责落盘与运行。
- **第 9 周｜数据复盘**：分析用户提供的视频数据，找出表现较好和较弱内容的可能原因；明确样本量限制，不把相关性说成因果。
- **第 10 周｜AI 评估**：协助写 AI 评估提示词初稿、边界条件和输出格式；由 Claude 接入，Gemini 交叉核对，Grok 扮演刁钻用户。
- **第 11 周｜产品关**：撰写新手引导文案、错误提示和隐私说明初稿；隐私与合规表述须由 Perplexity 查证并由用户确认。
- **第 12 周｜复盘关**：协助整理 12 周内容复盘、英文总结讲稿和下一阶段待讨论问题。

### 不建议交给 ChatGPT 独立完成的任务

- 实际代码修改、部署、密钥配置和 Git 提交：交给 Claude Code / Codex。
- 竞品数量、价格、平台政策、合规要求等外部事实调查：交给 Perplexity 做带出处研究，我负责把结果转成决策材料。
- 封面、横幅、结构图等视觉成品：交给 Gemini 或相应图像工具，我可以提供视觉 brief 和审阅意见。
- X 平台实时热点和原始用户声音收集：交给 Grok；我可以协助归纳与改写。
- 产品是否真正有需求：必须由真实用户试用、访谈和付费行为验证，不能由任何 AI 自己判定。

## 3. 我为用户设计的 12 周训练计划（第 3–12 周）

每周 ChatGPT 专项预计 **1–2 小时**。这是与 ChatGPT 讨论、练习和审阅的时间，不包含拍摄、剪辑、开发、外部调研或其他模型执行任务的时间。若当周主任务已经很重，优先完成必需交付，不额外堆叠练习。

| 周 | 用户要跟我练什么 | 交付物 | 怎么验收 |
|---|---|---|---|
| 第 3 周：Excel 自动报表 + 首条视频准备 | 明确首条视频讲给谁听、解决什么疑问；练习 5 种前三秒开场；逐段删掉口播稿中的书面语和空话；练习不看稿讲出主线 | 首条视频口播稿 v1；5 个开场钩子；前两条视频选题与一句话卖点 | 用户能讲清视频主旨；口播稿读起来顺畅；开场约 3 秒内交代冲突或看点 |
| 第 4 周：一键 PPT + 首条视频发布 | 写 10 个标题和 2 版简介；判断标题是否具体、可信、不夸张；校对 PPT 英文标题；根据“观众会划走的理由”逐项判断是否修改 | 标题与简介定稿；PPT 英文标题；发布前文案检查记录 | 标题准确反映内容；简介没有虚构成果；用户能解释选择最终版本的理由 |
| 第 5 周：产品化第一步 P2 | 用访谈法明确新用户是谁、想完成什么目标；区分用户目标、功能需求和实现方案；设计关键开局问题；讨论可行度判断的输入、输出与拒绝条件 | 新用户问卷初稿；目标可行度判断规则 v1；需求与功能对应表 | 每个问题都有明确用途；问卷能支持生成初步计划；规则不承诺学习结果或保证达成目标 |
| 第 6 周：Skill 提速做视频 + YouTube | 把“写好口播稿”拆成可重复步骤；比较清晰与含糊的 Skill / 命令说明；写 YouTube 频道简介草稿；练习用英文介绍频道定位 | 口播稿 Skill 需求说明；命令说明对照例；YouTube 频道简介中英文草稿 | 用户能说清 Skill 的输入、处理步骤、输出和限制；频道简介真实简洁，中英文意思一致 |
| 第 7 周：产品大纲与合规 P3 | 通过连续提问确定目标用户、场景、核心价值和非目标用户；区分必须有、可以后做、不做的功能；形成定价假设；根据 Perplexity 来源核对事实 | 产品大纲初稿；功能优先级表；待核实问题清单；定价假设 | 核心功能对应具体用户问题；定价标注依据或假设；事实、推测和待验证事项分开 |
| 第 8 周：写出自己的 Skill | 定义口播稿润色 Skill 的适用场景；写清不得改变的事实、语气和输出格式；设计 5 个测试样例（含失败样例）；根据测试结果修订规则 | Skill 规则文档；5 个测试输入及预期结果；修订记录 | 不擅自编造经历、数据或用户成果；保留用户原意；测试结果符合预期 |
| 第 9 周：自动化（只要求看懂） | 学会读播放、完播、互动等指标；对前 5 条视频做描述性比较；区分数据事实与原因假设；写简短周报 | 视频数据解读；一页周报；3 条下一步可验证假设 | 每条结论能追溯到数据；不因单条视频表现下普遍结论；每个建议都有验证动作 |
| 第 10 周：接入 AI 评估 P4 | 设计 AI 开局评估提示词；明确资料不足时如何追问；设计输出结构和风险提醒；准备边界案例检查模型是否过度承诺 | AI 评估提示词 v1；输出模板；10 个测试案例及预期判断 | 覆盖信息不足、目标过大、时间冲突和不合理目标；输出说明不确定性，不保证结果 |
| 第 11 周：产品 v1 收尾 P5 | 撰写新手引导；设计空状态、错误状态和求助文案；检查隐私说明是否讲清收集什么、存在哪里、谁能访问；对照真实产品校对 | 新手引导文案；关键提示语；隐私说明审阅意见 | 新用户能按文案完成关键步骤；隐私说明与实际数据处理一致；法律结论交专业人士核实 |
| 第 12 周：终章 P6 | 汇总选题、播放、完播、评论和制作耗时；总结有效与无效尝试；练习英文项目总结；根据证据提出下一阶段内容实验 | 12 周内容复盘；英文总结讲稿；第 2 个 12 周内容实验建议 | 结论有记录支撑；明确小样本限制；下一阶段建议可执行、可观察、可调整 |

### 每周固定协作方式

1. 用户提供本周实际材料，不为了 ChatGPT 重复整理一份材料。
2. 我先确认目标、受众、限制和完成标准；信息不足时只追问最关键的问题。
3. 我先给可审阅的初稿或练习，再根据反馈精准修改。
4. 涉及事实时标注“已知事实 / 假设 / 待核实”；外部规则和市场数据优先引用 Perplexity 的来源。
5. 用户确认后，再把文本交给 Claude 或其他负责执行的 AI；未经确认不把建议写成正式计划。

## 4. 需要用户提供什么

### 日常任务所需

- 当周 Claude 确认后的任务范围和完成标准。
- 视频选题、真实经历、目标观众、素材说明，以及用户希望保留的个人表达。
- 产品当前页面截图、功能说明、测试反馈或脱敏数据。
- 其他模型的输出或审查意见（仅在需要跨模型比较时提供）。

### 连接与权限

- **GitHub 读取**：本次会话已实际读取 ai-12week-lab、xiaoxuanzi-channel 和 quest-island 三个仓库。
- **GitHub 写入**：本次会话是否能创建分支、提交文件和发起 PR，以本次实际操作结果为准；不能仅凭读取成功推断写入权限。
- **Claude / Grok / Gemini / Perplexity**：不需要把账号密码交给我。需要引用其结果时，由用户粘贴必要内容或提供可访问链接。
- **客户资料、工作文件、健康数据**：只提供完成任务所必需的脱敏信息，不上传密码、API 密钥、客户机密或真实健康数据到项目仓库。

## 5. 风险和我做不到的事

1. **不能保证内容表现**：我能优化选题表达和结构，但无法保证播放量、完播率、粉丝增长或商业转化。
2. **不能替代真实用户研究**：问卷和访谈提纲只是工具；真实需求必须通过用户行为、访谈和付费验证。
3. **可能产生错误信息**：尤其是平台规则、法律合规、价格和模型能力变化；重要结论必须核对最新官方来源。
4. **不能默认跨平台同步**：我看不到其他 AI 的私有会话，也不能假设 Claude、Codex、Grok、Gemini 和 Perplexity 自动共享上下文。
5. **不应独立承担代码交付**：我可以解释代码、审阅方案和写清需求，但实际修改、运行、部署与回滚应由 Claude Code / Codex 执行并验证。
6. **不能替用户做最终决策**：课程调整、产品取舍、发布与否、预算和隐私边界由用户决定。
7. **不应把 AI 评估包装成权威判断**：冒险岛给出的目标可行度和计划建议只能作为辅助参考，必须明确假设和不确定性。
8. **注意隐私与密钥安全**：API 密钥不能放进网页前端、公开仓库或提示词；真实客户资料、工作资料和健康数据不得进入公开作品或不必要的仓库。

## 给 Claude 的协作建议

- ChatGPT 主要交付可审阅的文字、练习、提示词、问卷和分析，不与 Claude Code 争夺代码实现任务。
- Perplexity 负责外部事实研究，ChatGPT 负责把研究转化成产品决策问题和用户能理解的材料。
- Grok 负责提供外部平台的真实声音，ChatGPT 负责把声音整理成可验证的内容或产品假设。
- Gemini 负责视觉成品，ChatGPT 负责视觉需求 brief、文案和一致性检查。
- Codex 负责独立代码审查，ChatGPT 不把“看起来合理”当作代码通过验收。
- 每周 ChatGPT 专项控制在 1–2 小时；若当周时间不足，优先完成当周必交付，不额外增加课程负担。

**最终目标不是让用户更依赖 ChatGPT，而是让用户逐渐具备独立判断：什么时候需要我、什么时候应该换一个 AI、什么时候必须找真实用户或可靠来源验证。**
