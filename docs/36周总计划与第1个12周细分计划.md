## 2. 铁律和长期规则

### 2.1 铁律（用户明确定为铁律）

1. **GitHub 操作一律先用 GitHub Desktop**（11/12）：Desktop 做不到的（Pages、Issues、Actions、Release、合并 PR、仓库和权限设置）才用网页。适用于以后每一个 12 周计划，任何 AI 给用户写操作步骤都要遵守。
2. **技术决策铁律**（11/23）：需要用户拍板的硬核技术问题，先讲技术原因和原理。不懂就会严重误判的，作为新学习内容教到「基本掌握」；懂原理就能合理判断的，教到「明白了解」。两种都必须出实际测试题，确认达到才算。
3. **AI 层级铁律**（11/23）：Claude 和 Claude Code 权限最高，Claude 是唯一汇总协调人；ChatGPT 是二号 AI，Codex 归在 ChatGPT 名下同属第二级；Gemini、Grok（含 Grok Bot）平等，级别最低，主要作为工具。Perplexity 暂停使用（11/23 额度用完），恢复后作为三级调研备选。
4. **全部使用中文**（11/23）：关于这个项目的所有讨论、回复、文件和交付，一律用中文（代码、命令、专有名词除外）。适用于所有 AI。

### 2.2 长期规则

**操作方式**
- 绝不让用户打开终端敲命令；要敲命令的都由 Claude Code 执行，用户看懂用途后批准。
- Karpathy 四条规则（所有对话、所有项目）：先想清楚再动手，有歧义先问；只用最简单的办法；只改被要求改的地方；先说清「做完是什么样」，做完自查到达标。
- 软件、项目、文件尽量放 D 盘。

**验收**
- 只有经过 Claude 验收的才算完成；其他 AI 上做的成果要有截图或证明。
- 所有验收类任务由 Claude 验收，包括 Gemini、Grok 的交付。
- 验收对话一开始，先确认 quest-island 仓库已接入并有推送权限。

**计划怎么定**
- 「学多少技术」让位于「能否独立用起来」。
- 三线并重：内容、产品、技术基础同等分量；英语和健身是每天的底盘。
- **发掘和高效利用 GitHub 是最高优先级**（11/23）：GitHub 是贯穿内容和产品两条线的工具箱，每周 GitHub 关是必做关，权重和内容关相同；每周的工具必须用在当周的视频或产品上。
- **用户在 B站、X、抖音等渠道找到的工具或 Skill**（不限于 GitHub，凡是 AI、GitHub、自媒体用得上的高效工具都算），发给 Claude 或对应的 AI 做交叉验证；确实能实现宣传的大部分功能的，找到详细资料，随时加进计划并学会使用。
- **每周一自动扫描**：Claude 每周一早上自动扫描一次和目标相关的热门 GitHub 工具，给出 1–2 款核实过的候选（11/23 用户同意设置）。
- 任务要具体详细、有真正的技术含量；太简单就加量或提前；完成过的内容不再出现；提前做完就当周加新任务。
- 计划不一次定死，36 周计划随进度调整。

**改计划的流程**
- 用户批准后才能改 PLAN.md、冒险岛和 DECISIONS.md。
- 意见先攒着，确认后一次改完。
- 顺序：用户审核 → 提交 GitHub 让各 AI 读 → 各方确认 → 最后改冒险岛。

**产品**
- 目标闯关计划工具 12 周内必须完成、不能放弃；第一个可售卖版本必须带 AI 评估，做到 3 位真实用户试用 + 小红书上架。
- 产品任务优先于拓展任务；做完一项就问要不要把下一项提前；产品任务做完前不碰拓展任务。
- 奖励价格：全部任务做完刚好买下全部衣橱奖励，只剩一点；完成大部分差不多够；漏太多就有买不起的。

**安全和隐私**
- 真实健康数据（包括身高体重等身体数据）、工作资料、客户信息、私人聊天、未获授权内容，不进任何仓库（私有仓库也不行）。
- API 密钥只放在云函数平台的环境变量里，不进网页、仓库、截图、日志和任何对话。
- 真人照片不放进公开仓库；验收说明不写安全设置细节。

**复盘**
- 每周复盘六行：在「下周改什么」下面加「如何更改」。

## 3. AI 分工和权限

### 3.1 三级权限

| 级别 | AI | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 一级（最高） | Claude、Claude Code | 用户批准后改核心文件（PLAN、DECISIONS、HANDOFF、WEEKLY_STATUS、README、CLAUDE.md、AGENTS.md 等）；审核并合并别人的 PR；唯一汇总协调人；实现产品和验收 | 不经用户批准改计划 |
| 二级 | ChatGPT、Codex（归在 ChatGPT 名下） | 发 PR 新增建议文件；发 PR 提议修改核心文件（由 Claude 审核）；ChatGPT 在英语、文案、需求文字上的初稿默认采用，Claude 只挑问题；Codex 只读审查代码，用户指定时才改代码 | 直接改 main；自己合并 PR |
| 三级（工具） | Gemini、Grok（含 Grok Bot） | 只在 `docs/建议/<名字>/`、`docs/调研/` 下**新增**自己的文件，作为素材给上两级用 | 修改任何已有文件（包括 HANDOFF.md） |

### 3.2 协作规则

1. **一件事一个负责人、一个审查者**，不让每家对每件小事都发表意见。
2. **默认 Claude Code 实现、Codex 只读审查**；要改代码时由用户指定本轮唯一修改者。
3. **只在自己的分支上改、发 PR**，分支名用英文：`<AI 名>/<任务名>`，比如 `perplexity/p1-research`。
4. **不能写仓库的 AI**（目前 Gemini、未连接时的 Grok）在对话里交付，由用户转交 Claude 代为提交。
5. **调研结论必须附出处**：合规和平台规则由 Claude 查、Gemini 独立交叉核对；竞品和定价由 ChatGPT 查、Claude 抽查出处；需要专业人士确认的单独标出。X 上的声音以 Grok 为准；视觉以 Gemini 为准；产品有没有需求以真实用户为准。
6. **重要改动上线前做一次 Codex 只读审查**：第 5、10、11 周。
7. **视觉交付**：Gemini 出底图和主视觉，同时给一份《文字排版与配色参数卡》（主副标题、字号比例、字体风格、色号）；图上的中文大字和卖点标签由用户在剪映或 Canva 里叠加，避免 AI 写错字反复返工。
8. **Grok 额度**：11/26（周四）恢复，之前不排 Grok 任务。
